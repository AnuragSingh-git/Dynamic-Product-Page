# Dynamic Product Page — EMI Plans backed by Mutual Funds

A full-stack web app that displays products (smartphones, headphones, watches, etc.) with
multiple variants and dynamic EMI plans, similar to Snapmint. All product, variant, and EMI
data is stored in MongoDB and served through a REST API — nothing is hardcoded on the frontend.


---

## Tech Stack

| Layer      | Technology |

| Backend    | Node.js, Express 5 |
| Database   | MongoDB (Atlas), Mongoose ODM |
| Deployment | Frontend → Vercel, Backend → Render |

## Schema Used

Everything lives in a single `products` collection. EMI plans and variants are **embedded**
inside each product document (not separate collections), because they're always read together
with the product and never queried independently — this avoids extra lookups on every page load.

### Product

| Field       | Type              | Notes                                  |
|-------------|-------------------|-----------------------------------------|
| name        | String            | required                                |
| slug        | String            | required, unique — used in the URL      |
| brand       | String            | required                                |
| category    | String            | default: "Smartphones"                  |
| description | String            |                                          |
| variants    | [Variant]         | min 2 required                          |
| emiPlans    | [EmiPlan]         | min 1 required                          |
| timestamps  | createdAt/updatedAt | auto-generated by Mongoose            |

### Variant (embedded)

| Field   | Type     | Notes                                  |
|---------|----------|------------------------------------------|
| color   | String   | required                                  |
| storage | String   | required (also used for size/capacity, e.g. "42mm", "1TB") |
| price   | Number   | required — selling price                  |
| mrp     | Number   | required — strikethrough price             |
| images  | [String] | required, min 2 — image gallery for this variant |
| stock   | Number   | default 10                                 |

### EmiPlan (embedded)

| Field         | Type   | Notes                                       |
|---------------|--------|-----------------------------------------------|
| tenureMonths  | Number | required, e.g. 3, 6, 12, 24, 36                |
| interestRate  | Number | required, default 0 (e.g. 0 or 10.5)           |
| cashback      | Number | default 0                                      |

Note: `monthlyAmount` is **not stored** — it's calculated on the frontend
(`lib/emi.js`) from the selected variant's `price` and each plan's `tenureMonths`/`interestRate`.
This keeps the EMI amount always correct for whichever variant the user has selected, instead of
storing a monthly amount that only matches one price.

## Setup & Run Instructions

### Prerequisites
- Node.js 18+
- A MongoDB Atlas connection string (or local MongoDB)

### 1. Backend

```bash
cd backend
npm install
cp .env.example .env
# then edit .env and paste your own MONGO_URI
npm run seed     # populates the database with 10 sample products
npm run dev      # starts the API on http://localhost:3000
```

`.env` variables:
```
MONGO_URI="your-mongodb-connection-string"
PORT=3000
CORS_ORIGIN="http://localhost:3001"
```

### 2. Frontend

```bash
cd frontend
npm install
cp .env.local.example .env.local
# NEXT_PUBLIC_API_URL=http://localhost:3000/api
npm run dev -- -p 3001    # starts on http://localhost:3001 (3000 is taken by the backend)
```

Visit `http://localhost:3001` to see the product list, and click into any product to see
`http://localhost:3001/products/<slug>`.

## Deployment

- **Backend:** deploy `backend/` to Render as a Web Service. Set `MONGO_URI` and `CORS_ORIGIN`
  (your deployed frontend URL) as environment variables on Render.
- **Frontend:** deploy `frontend/` to Vercel. Set `NEXT_PUBLIC_API_URL` to your deployed backend
  URL + `/api` as an environment variable on Vercel.

## Seed Data

`backend/seed/seedData.js` seeds 10 products across categories (smartphones, headphones,
smartwatches, gaming console), each with 2–3 variants and their own EMI plan list. Run
`npm run seed` from `backend/` to (re)populate the database — this clears the `products`
collection first, so it's safe to re-run.
